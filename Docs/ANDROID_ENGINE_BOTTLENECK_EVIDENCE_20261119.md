# Android engine bottleneck evidence — 2026-11-19

Target: Unity 6000.3.26f1 / URP 17.3.0 / Snapdragon 680 / Adreno 610 / 4 GB RAM. This is a **source/settings audit**, not a confirmed explanation of the phone's freezes, 3–30 second stalls or process exits.

## Claims checked against canonical main
1. **GPU/Vulkan:** `ProjectSettings.asset` has Android `m_Automatic: 0`, `m_APIs: 0b000000` (OpenGLES3 enum 11). This saved configuration is not Vulkan-first. Whole-device freezes cannot be classified as GPU deadlocks without Android/driver traces. `AarisMobileRuntime` sets a 60 FPS target; the player can switch to 30 FPS.
2. **Physics backlog:** `TimeManager.asset` fixed timestep is approximately 20ms and maximum allowed timestep was 333.3ms; up to ~16 fixed updates can be due in a large stall. **Targeted mitigation:** for Android-only budget-class GPUs with reported RAM <=4608 MB, `AarisMobileRuntime.Awake` limits `Time.maximumDeltaTime` to at most six fixed steps (normally 120ms), only if the original is greater. The unchanged fixed step keeps normal-frame vehicle and character physics frequency. It restores the original cap on teardown only if another subsystem has not overwritten the applied value. Trade-off: after pathological stalls, simulation time may advance less than wall-clock time rather than endlessly catching up. Runtime JSON diagnostics expose `fixedPhysicsStepMs` and `maxPhysicsCatchupMs`.
3. **Terrain:** four native binary TerrainData files are ~53–54MB **serialized on disk each**; these bytes do not directly equal GPU/PSS usage. Project scripts do not call runtime `SetDetailResolution` or `SetDetailLayer`; large terrain detail rendering may still incur cost, but a specific runtime detail rebuild and alleged 5–15s stalls remain unverified.
4. **AI:** `AarisOfflineBRDirector` configures six rivals, not 50 NavMesh agents. The project deliberately uses no runtime NavMesh queries. Rival Animator uses `CullUpdateTransforms`, with distance-throttled AI after 90m. The local player's `AlwaysAnimate` is a different object.
5. **Audio/imports:** 45 local WAV files total 865,329 bytes on disk; importers contain 41 default `loadType: 0` and 4 `loadType: 1`. There is no 50MB music file or proof of 400–600MB decoded audio. In the scanned model importers eight explicitly set `isReadable: 1`; among 297 scanned texture importers one does. Do not blindly remove CPU readability; mesh/texture users must be checked first.
6. **URP:** saved HighQuality pipeline asset enables HDR, 4x MSAA, Depth and Opaque textures, 4 cascades and 1000m shadows, with SRP Batcher enabled. Android constrained-GPU runtime already caps MSAA to 2x and shadow range to 120m. Saved values are **not** effective on-device values. Depth/Opaque textures have a cost, but do not prove that the entire map is rendered 2–3 extra times each frame. No visual-quality or native TerrainData edits were made.

## Device evidence required
Obtain cold-launch and extended-match Unity Profiler main/render/GPU frame times, physics FixedUpdate counts, texture residency, Android PSS and peak graphics memory; capture `adb logcat`, system ANR traces, low-memory kill records and vendor GPU reset/tombstone evidence where available. Compare baseline vs patched APK on the same handset. The headless Unity Editor may not compile without a valid owner-activated Editor license; static tests are not compilation or gameplay proof.

Relevant official Unity docs: physics fixed timestep and Maximum Allowed Timestep; Android Graphics API selection; audio clip load types; URP mobile rendering configuration.
